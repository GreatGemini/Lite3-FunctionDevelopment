# Rover Desk / 机器狗工作台 0.2.2

告警页：紧急为低于20%电量、基本状态8和本软件UDP状态中断；一般为20%至35%以下电量、SSH及视频中断。通信检测有10秒连接宽限期。过温、过流、跌倒与原厂App断连暂无可靠告警源，显示未判定。电脑扬声器播放两声高音后停顿3秒（紧急）或两声低音后停顿5秒（一般），紧急优先；支持静音，手动断开停止声音。本次运行保存最近300条告警变化记录，不跨重启保留。

文字 / 语音页支持手册15个动作口令。输入或填入不会执行，点击“执行指令”才发送；麦克风尚未接入。先连接并启用遥控、确认姿态。平移1秒后停止；起立/趴下和打招呼根据明确状态反馈确认完成，不再固定4秒追加停止。其他动作没有可靠完成标志，15秒超时停止并锁定，不能视为正常完成。原厂文字动作不使用手动速度档位。

控制会话与按钮权限分离：第一次启用遥控后维持4Hz心跳。失焦停止手动移动和平移口令、锁定输入，离散动作继续监测；显式停止、关闭遥控、保护或遥测中断会停止活动动作，心跳仍保持。断开连接先停止动作，再结束心跳。程序启动或仅连接而未启用遥控时不发送心跳。新增事件记录包含失焦、动作完成、停止原因和会话关闭。修改后需逐项实机验证。

总览的速度条为1—5档，重连恢复1档，移动中不能换档。该档位调节轴指令幅度，不代表米/秒，保持慢速步态。

Windows 原生应用：Lite 3 状态、摄像头、桌面运动遥控、只读 MCP。适配器结构可扩展其他机型。打开 release/RoverDesk/RoverDesk.exe，必须保留整个文件夹。

## 连接

机器人 192.168.1.120，控制端口 43893；电脑原地址 .100，临时接收地址 .103，状态端口 43897。RTSP 为 rtsp://192.168.1.120:8554/test。
SSH 用户 firefly，密码仅保存在进程内存。不输入密码也可收 UDP 和视频，日志采集需要密码。

普通双击启动保持未连接。点击“连接设备”启动 UDP 和摄像头，并使用输入的密码连接 SSH；点击“断开连接”停止三路采集并锁定遥控。
接收端监听所有本机 IPv4 地址的 43897 端口，并仅接受配置中的机器狗来源 IP。本机发送 IP 用于 SSH 和控制，不再限制状态接收。
SSH 密码不跨重启保存；重开后输入密码并点击“连接设备”可恢复电池百分比、温度等日志。UDP 状态和视频不受密码影响。
连接不会自动启用遥控或发送心跳/动作。应用不修改机器人配置文件、IP、持久参数，不重启服务。实际遥控会发送手册定义的运行模式命令：手动控制、移动模式、低速步态、关闭持续踏步。

## 运动遥控

1. 在机器狗旁确认环境和姿态，并保持原厂遥控器可用。
2. 有效基本状态为 1、6、9 时自动识别趴下或站立；仅状态码 98 显示“现场姿态”供人工确认。数据过期时等待有效实时状态。
3. 勾选“启用遥控”，开始 4 Hz 心跳。启用本身不发送起立或行走指令。
4. 已站立时按住方向按钮移动，松开归零。前进、后退、左右转弯、左右横移一次只能使用一个方向。
5. “停止 / Esc”归零三个轴，保留心跳。“软件急停”发送厂商软急停并锁定遥控；不能替代实体急停，恢复依照原厂说明。
6. 起立、趴下底层共用一条切换指令。程序校验当前姿态，只发送一次，四秒内阻止下一次姿态/移动操作。未知状态 98 每次切换后都需重新现场确认实际姿态，不把发送成功当成动作完成。
7. 窗口失焦、断开连接或关闭时归零并锁定，停止本程序心跳。停止心跳后行为取决于原厂固件，不保证继续站立；只暂停移动时请用“停止 / Esc”。
8. 重连、重新启动不会自动恢复控制。MCP 无运动写入工具。

控制约 25 Hz，界面每 40 ms 续期按住意图；超过 180 ms 未续期即归零。整机遥测超过 0.5 秒或进入保护等不允许状态时归零并锁定。
低挡摇杆值固定为前后 ±9000、横移 ±14500、转弯 ±11500，均超过手册死区；它们不是 m/s 或 rad/s，实际速度尚未运动标定。不开放高速、跳跃、翻滚动作。

## 状态覆盖及边界

已实测 68 个实时字段（包含各坐标分量和枚举原值），UDP 0x0901/0902/0903 各约 100 Hz，SSH、视频可同时在线。
- UDP：基本/步态/运动状态、姿态、角速度、加速度、位姿、机身系及世界系速度、超声波、归零、平衡需求、电量原值、12 个关节角度和角速度。
- 实时 SSH 日志：电池百分比、电压、温度，12 个电机温度，陀螺仪连接、电压正常、控制端连接标志，动作文字提示。
- SSH 诊断：主机名、架构、运行时长、原厂服务、活动日志和上报配置。
- RTSP：640×480，支持保存实时 JPEG；超过三秒的画面不能作为实时图导出。

基本状态 98 显示“未知状态”。位姿/速度中的 0 是上报原值，未验证定位精度。
charging、error_state、task_state、touchdown 为所查手册的无效占位字段，不解释为正常。日志动作提示不代替基本状态。
UDP 超过三秒、日志超过十五秒标记过期。日志采集跳过历史内容。

实机 0x0906 载荷 368 字节，与支持的 332/336 字节 SDK 布局不同，暂不解析；扭矩、足端力、SDK 时标未确认。0x0904/0905 等未知结构不猜测。扬声器状态仅接收 0x11050F08 反馈，不主动查询。

## MCP

默认 http://127.0.0.1:8766/mcp，仅监听本机并验证 Bearer 令牌。可在“AI / MCP”页复制连接配置。
工具：list_robots、get_robot_state、get_joint_states、get_diagnostics、get_camera_frame。
资源：robot://current/state。字段带来源、单位、数据年龄及过期标记。
motion_control 表示桌面能力；mcp_motion_control 为 false。AI 不能发送运动或任意 SSH 命令。

## 不改机器人配置的接收方法

电脑“以太网 4”（接口 10）增加临时 .103/24，保留 .100、DHCP、网关、DNS，附加地址设置 SkipAsSource。机器人原样向 .103:43897 上报。

仅关闭重开软件不会删除接收地址。电脑重启后临时地址失效。检查接口和 .103 占用后，以管理员身份运行 enable_pc_receiver.ps1。脚本针对接口 10 和原地址 .100，不符合条件时停止。
恢复电脑改动可运行 disable_pc_receiver.ps1。恢复后 UDP 接收停止。脚本不登录或修改机器人。

## 开发和验证

main.py 为入口；rover/motion.py 为遥控及联锁；adapters.py 为机型适配与采集；protocol.py/model.py 为严格解析和状态；ui.py 为界面；mcp_bridge.py 为只读服务。
build.py 生成 Windows 程序，vendor 为依赖。

29 项 unittest 测试通过：协议、字段有效性、MCP 鉴权、UDP 接收、运动封包、停止超时、姿态联锁、Qt 按下/松开/失焦等。
运动测试仅使用模拟发送器和 127.0.0.1 回环，没有驱动机器狗实际运动。实体动作效果和速度仍需现场验证。

协议依据：本地 Jueying Lite3 Motion Host Communication Interface(beta) V1.0.7-0.pdf（控制章节第 7–12 页及状态定义）；官方 https://github.com/DeepRoboticsLab/Lite3_MotionSDK 。
