# Rover Desk 0.3.0 房间巡检开发版

本版增加人工遥控巡看、自动采图、OpenAI 云端物品分析和带截图的报告。
原交接包保留不动，运动控制实现沿用原版，不增加自主运动。

## 启动

双击本目录的 `启动巡检版.cmd`。默认不连接机器人，不启用遥控。
本开发副本通过 `vendor/bundled-dependencies.pth` 使用原交接包内的依赖，启动脚本也引用原交接包的 Python。
因此当前电脑上应保留原交接包位置；这是本机开发版，不是独立便携发行包。
原交接包缺少 Pillow 时，先按 requirements.txt 补齐原 vendor 中的 Pillow。

本版配置保存在 `%LOCALAPPDATA%/RoverDesk-Inspection`，与旧版分开。
MCP 使用本机端口 8776。首次启动使用随工程的设备配置；SSH 密码仍需每次输入。
不要同时用新旧两个版本连接同一机器人，尤其不要同时启用遥控或竞争视频连接。
电脑临时 .103 接收地址等网络准备与原版相同。本目录旧网络脚本仍针对旧网卡，不要在当前电脑照搬执行。

## 一次巡检

1. 关闭旧版或在旧版断开设备，在本版连接机器狗，确认视频实时出图。
2. 打开“房间巡检”页，填写 OpenAI API Key 和有权限使用的视觉模型名称。默认示例为 `gpt-4.1-mini`，可更改。
3. 选择采图间隔和图片上限，默认每 5 秒、最多 20 张。勾选本轮图片上传授权。
4. 点击“开始巡检”，然后切换到“总览”，按原方式启用遥控并人工巡看。
5. 缓慢移动，在不同角度停稳，让摄像头看清物品。软件后台采图，跳过近似重复或明显低清晰度画面。
6. 巡看完毕，先停止移动，再到“房间巡检”点击“结束巡检并分析”。
7. 软件发送一次包含本轮图片的云端请求，并汇总物品名称、类别、外观、颜色、可见文字、画面位置、数量下限、识别把握和截图编号。
8. 双击物品行打开第一张依据截图；“导出报告和截图”复制本轮完整报告目录并打开 HTML 报告。

达到图片上限或 10 分钟采集时限后，软件自动进入分析。巡检采集的结束不代替遥控停止。
切换软件内部页面不会结束采集。窗口失焦仍遵守原遥控锁定规则。

## 摄像头暂时不可用时

可使用“导入照片分析”，一次导入 1—24 张 JPEG、PNG 或 WebP 照片，无需连接机器狗。
导入照片保留全部选定视角，不使用自动采图的模糊/重复过滤。
拍摄时间记录为本轮导入时间，不是照片 EXIF 时间。

## 数据、费用和限制

- 图片会上传到 `https://api.openai.com/v1/responses`，需要 OpenAI API Key 和可用 API 额度。SSH 密码不能代替 API Key。
- API Key 仅留在本次软件内存，可从 `OPENAI_API_KEY` 环境变量读取；不写入配置、报告或错误日志。
- 普通设置只保存模型名、间隔、图片上限。图片及报告保存在数据目录的 `inspections/本轮编号`。
- 每轮默认一次云端请求；失败不会自动重复扣费请求，“重试分析”会发起新请求。取消不能撤回已发送的请求，云端可能仍计费。
- 请求设置 `store=false`；这不等于对服务商所有数据保留行为作保证，具体以服务商数据政策为准。
- 物品识别、跨视角合并和数量估计可能出错。数量为保守可见下限，不是完整库存；图像位置不是地图坐标。
- 近似图像筛选是启发式处理，可能跳过细微差异；需要保留某些细节时可拍照后导入。
- 所有结果只用于查看，不反馈到运动控制，不执行画面里出现的指令。

每轮目录包含：

| 内容 | 用途 |
|---|---|
| `frames/F001.jpg` 等 | 缩放并去除原 EXIF 的巡检依据图片 |
| `session.json` | 采集参数、截图编号、时间和筛选统计，不含密钥 |
| `report.json` | 结构化物品清单、模型名、返回用量和生成时间 |
| `report.html` | 可在浏览器打开的报告和图片依据 |

## 开发验证

双击 `运行巡检测试.cmd` 运行离线回归。新增测试使用合成图片和模拟云端响应，不上传实际照片、不发送机器狗运动指令。
云端真实账号调用和实体摄像头巡看需在用户填写密钥后验证。
